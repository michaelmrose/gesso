** Required causal distinctions

An invalidation or advisory is not a DOM mutation permission. Under
automatic policy the coordinator can issue a read acquisition; under
explicit-refresh policy a trusted Refresh click grants an idle acquisition.
A busy click is not permission for a successor. Both policies require the
actual pending grant at configuration and physical request binding, with
the current owner and target. A configuration event is not evidence that
the request was sent; a successful HTTP terminal event is not adoption.
Only an admitted swap followed by the correlated adoption observation
can discharge the applicable acquisition debt. A rejected or abandoned
acquisition preserves its outstanding requirements subject to owner retirement.

A grant identifies a cooperative browser lifecycle action, not an
authenticated HTTP principal, an authorized subscription, a database read
basis, or an independent receipt of physical execution. The server must
still authorize the actual read and subscription at its own boundaries.
