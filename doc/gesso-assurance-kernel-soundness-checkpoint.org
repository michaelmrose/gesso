* Mathematical claims must be separated

** S1 — Typed source interpretation

The intended typed-atom correspondence is, for every valid source expression
=e=, declared environment =Delta= and valid partial state =s=:

#+begin_example
  Admitted(e, Delta) AND WF_Delta(s)
    => Eval_Production(e, s) = Interpret_Independent(e, s)
#+end_example

A correct result includes definedness/rejection behavior. Optional absence,
present nil, and present false are separate cases; nominal enum identity,
short-circuit branch admission, and typed reader footprints matter. The
v1427--v1428 tests and v1430--v1431 mutations provide substantial sampled
correspondence and rejection evidence. They do not prove this quantified
statement for every admitted declaration and runtime binding.

** S2 — Propositional proof rules and premises

The production checker at
=src/gesso/assurance/proof/kernel.clj= has exactly seven admitted rules:

| Rule | Required local justification |
|------+------------------------------|
| =:premise= | Selected named premise is available; it stays OPEN |
| =:truth-introduction= | =true= is valid without a cited premise |
| =:implication-reflexivity= | =P => P= is valid without a cited premise |
| =:conjunction-introduction= | All cited conjuncts imply their conjunction |
| =:conjunction-elimination= | A cited conjunction implies its selected child |
| =:implication-elimination= | =P => Q= and =P= imply =Q= |
| =:disjunction-introduction= | A cited disjunct implies the containing disjunction |

The independent reference vocabulary is in
=src/gesso/assurance/proof/propositional_rule_obligations.clj= and the
truth-functional interpretation in =propositional_semantics.clj=.
For every accepted proof step with inherited open premises =Gamma=, the
semantic requirement is =Gamma |= conclusion=. This requirement is not
satisfied by dropping, relabeling or implicitly discharging =Gamma=.

The source includes independently written local rule checks, mutation suites,
source-relative normalizer audit, derivation composition, and checks of
premise preservation across alternative checking routes. These support a
conditional induction-on-proof-steps argument. They do NOT yet establish a
machine-checked, universal correctness theorem for production normalization
or for every possible program path through the kernel. No arbitrary atomic
truth axioms, arithmetic solver, excluded-middle axiom, or hypothesis
discharge may be silently added to the seven-rule fragment.

** S3--S5 — Initial states, guarded transitions and induction

Let =B= be the exact DECLARED initial-state set, =O= the exact DECLARED
operation catalog and =T_o= an admitted abstract transition. The desired
abstract invariant statement is conditional on:

#+begin_example
  BASE: for every b in B, I(b)
  STEP: for every o in O and all well-typed s,x,s',
          I(s) AND T_o(s,x,s') => I(s')
  CLOSURE: every abstract execution begins in B and uses only o in O
  ------------------------------------------------------------
  for every finite declared execution s0,...,sn: all I(si)
#+end_example

The independent abstract transition relation enforces the source guard,
SIMULTANEOUS assignments from prestate/inputs, exact writer footprints, and
frame equivalence including optional-field presence. The restricted
preservation schemas cover frame, fixed literal, same-origin field copy,
and supported conjunction composition. An undefined read, false guard,
wrong copy origin, unmodeled field write, or omitted conjunct must not
be accepted as a matching transition or as a whole-invariant proof.

The v1432--v1437 tests provide independent finite witnesses, counterexamples,
mutation checks, per-step derivation checks, and bounded-history induction
audit. A complete catalog relative to a developer-supplied SOURCE does not
establish that all actual production writers have been discovered. A single
extra physical writer invalidates a deployment-level completeness inference,
even if the smaller declared machine is consistent.

* Assurance claim ladder and promotion restrictions

| Claim class | Permitted wording | Promotion requirements |
|-------------+-------------------+------------------------|
| Source admitted | Exact declaration passed well-formedness checking | Source-bound current checker result |
| Finite semantic correspondence | All enumerated cases agree / counterexample found | Concrete universe and bounds; nonvacuity recorded |
| Checked conditional derivation | Conclusion follows *if* named premises hold | Exact named premises retained; independent rule correspondence appropriately scoped |
| Declared abstract induction | Every declared finite history preserves I IF base/step/closure are sound | Complete declared catalog, all clauses, all local premises |
| Source-bound in-process certificate | Current source and declared graph rechecked in trusted JVM | Current handle + graph; no inferred deployment authority |
| Production physical certification | NOT YET ADMITTED | S6--S9 and relevant nine physical obligations soundly discharged or explicitly scoped |
| General cross-runtime refinement | NOT YET ADMITTED | JVM/CLJS/DOM/SSE/HTMX trace mapping and trusted browser effect realization |

No positive instance of the first five categories may be silently rewritten
as the sixth or seventh. A false or unproved premise remains OPEN even when
other parts of the derivation are satisfied. A deliberately narrower, valid
catalog describes a narrower model; it cannot inherit assurance over a
larger external application.

* Handover to v1440–v1451 — compositional application assurance

v1440 should USE the already-existing =gesso.assurance.dependency=,
=proof/induction_dependency.clj= and certificate/dependency checks as the
starting point, not create a duplicate generic dependency-graph engine.

The next material advance is a source-derived end-to-end dependency closure
for *supported* application assurances: business rule -> typed semantic source
-> operation catalog -> initial and preservation obligations -> checked
proof -> issued operation -> installed entry points -> physical and browser
obligations. Every unresolved edge is an explicitly typed assumption.

A useful v1451 pilot is NOT a dashboard showing many green local checks. It
is one small, real, single-node Gesso application constructed using ordinary
APIs whose reported assurance has a checkable source identity, exact claim
scope, complete declared operation and invariant coverage, and honest open
physical/browser premises. An adversarial missing writer or stale proof
must prevent the stronger claim. Formal specifications remain internal.

* Final verdict

At v1439, Gesso has accumulated serious independent evidence for its
restricted abstract semantics, proof derivations, and declared-machine
induction. The source-level conditional mathematics is much better supported
than at the original R4 snapshot. The unfinished work is NOT another report
shape: it is independent universal semantic justification and the trustworthy
bridge from declarations to installed, actually executed applications.

This document records that boundary without changing it.
